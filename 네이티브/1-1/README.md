# 1. 프로젝트 개요

## 1.1 미션 소개 및 수행 배경

본 프로젝트는 대규모 언어 모델(LLM)의 특성을 이해하고, 프롬프트 엔지니어링 기법을 활용하여 실제 업무에 적용할 수 있는 자동화 프롬프트를 설계하는 것을 목적으로 한다.

AI 교육사업 퍼실리테이터로서 교육생 진도관리, 참여 현황 관리, 교육 운영 보고 등의 업무를 수행하며, 반복적인 데이터 정리와 보고서 작성에 소요되는 시간과 노력을 줄이고자 본 과업을 선정하였다.

특히 AI 관련 비전공자도 이해하고 활용할 수 있는 프롬프트를 설계하는 데 중점을 두었다.

본 프로젝트에서는 단순히 AI를 활용하여 보고서를 생성하는 것을 넘어, 다음 과정을 직접 수행한다.

1. 동일한 업무 과업을 여러 LLM에 적용하여 성능을 비교한다.
2. 평가 기준과 근거를 바탕으로 적합한 모델을 선정한다.
3. 페르소나와 시스템 프롬프트를 설계한다.
4. Zero-shot, Few-shot, 단계적 추론 유도 기법을 적용한다.
5. 환각 및 문맥 유지 문제를 검증하고 프롬프트를 개선한다.

# 2. LLM 모델 비교 및 선정 보고서

## 2.1 모델 비교 목적

동일한 교육생 진도관리 데이터를 입력했을 때, 서로 다른 LLM이 생성하는 보고서 개요의 품질을 비교한다.

특히 교육사업 운영 업무에서 중요한 다음 요소를 중점적으로 평가한다.

- 데이터와 수치의 정확성
- 보고서 목차 및 구성의 논리성
- 핵심 메시지 도출 능력
- 주요 리스크 분석 능력
- 요청한 출력 형식의 준수 여부
- 불확실하거나 누락된 정보에 대한 처리 능력

모델 비교는 단순한 선호도가 아닌 정량적 점수와 실제 응답 근거를 기준으로 수행한다.

## 2.2 비교 대상 및 사용 환경

| 구분 | 모델 | 사용 채널 | 요금제 | 테스트 날짜 | 주요 설정 |
|---|---|---|---|---|---|
| 모델 A | GPT-6 | ChatGPT 웹 | 확인 필요 | 확인 필요 | 확인 필요 |
| 모델 B | Claude Sonnet 5.5 | Claude 웹 | 확인 필요 | 확인 필요 | 확인 필요 |
| 모델 C | Gemini 자동 모드 | Gemini 웹 | 확인 필요 | 확인 필요 | 자동 모드 |

모델 비교 시 다음 조건을 적용한다.

1. 세 모델에 동일한 프롬프트를 입력한다.
2. 각 모델에서 새로운 대화를 시작한다.
3. 이전 대화 문맥을 활용하지 않는다.
4. 최초 생성된 결과를 기준으로 평가한다.
5. 별도의 추가 지시나 외부 자료를 제공하지 않는다.
6. 모델별 실제 출력 결과와 평가 근거를 기록한다.

**재현성 확보를 위한 기록 사항**

- 모델명 및 사용 모드
- 사용 요금제(무료/유료)
- 사용 채널(웹)
- 실제 테스트 날짜(YYYY-MM-DD)
- 주요 설정(temperature, top_p, max_tokens 등)
- 웹에서 설정 확인이 불가능한 경우 '웹 기본값 / 사용자 설정 불가'로 기록
- 무료 요금제 이용 시 해당 요금제의 제한사항 기록

※ Gemini 자동 모드는 실제 응답 처리에 사용된 내부 모델이 표시되지 않을 수 있으므로, 확인되지 않은 모델명을 임의로 기재하지 않는다.

## 2.3 업무 과업 및 테스트 데이터

### 선택 업무 과업

**교육생 주간 진도관리 보고서 개요 생성**

교육생의 수강 상태 및 진도 데이터를 분석하여 교육사업 팀장에게 제출할 보고서의 목차, 핵심 메시지, 주요 리스크 및 후속 조치 방안을 작성하는 업무이다.

### TEST 01 입력 데이터

| 항목 | 입력값 |
|---|---|
| 보고서 유형 | 교육생 주간 진도관리 현황 |
| 보고 목적 | 교육생의 학습 진행 현황 및 관리 필요 사항 보고 |
| 보고 대상 | 교육사업 팀장 |
| 기준일 | 2026-11-20 |
| 교육 과정 | AI 활용 실무 교육 |
| 전체 교육생 | 50명 |
| 정상 수강 | 38명 |
| 진도 지연 | 8명 |
| 미참여 | 4명 |
| 평균 진도율 | 76% |
| 목표 진도율 | 80% |
| 특이사항 | 일부 교육생의 학습 진도가 목표에 미달 |

※ 해당 데이터는 모델 성능 비교를 위해 작성한 가상 데이터이며, 실제 교육생 개인정보를 포함하지 않는다.

### 기대 정답 및 검증 기준

| 검증 항목 | 기대 결과 |
|---|---|
| 정상 수강 비율 | 38/50 = 76% |
| 진도 지연 비율 | 8/50 = 16% |
| 미참여 비율 | 4/50 = 8% |
| 관리 대상 인원 | 8+4 = 12명 |
| 관리 대상 비율 | 12/50 = 24% |
| 수강 상태 합계 | 38+8+4 = 50명 |
| 목표 대비 평균 진도율 차이 | 76%-80% = -4%p |

**주의 사항**

- 정상 수강 비율과 평균 진도율은 모두 76%이지만 서로 다른 지표이다.
- 목표 대비 4%p 미달은 이전 대비 4% 감소했다는 의미가 아니다.
- 진도 지연 및 미참여 교육생이 전체 평균 진도율에 미친 구체적인 영향은 개인별 진도 데이터 없이 확정할 수 없다.

## 2.4 TEST 01: Zero-shot 공통 프롬프트

### 실험 목적

Few-shot 예시나 단계적 작업 절차를 제공하지 않은 상태에서, 세 모델의 기본적인 보고서 개요 생성 성능을 비교한다.

### 프롬프트 v1.0

```text
당신은 AI 교육사업 운영 담당자의 보고서 작성을 지원하는 AI 어시스턴트입니다.

아래 교육생 진도관리 데이터를 분석하여 교육사업 팀장에게 제출할 주간 진도관리 보고서의 개요를 작성해 주세요.

### 입력 데이터

- 보고서 유형: 교육생 주간 진도관리 현황
- 보고 목적: 교육생의 학습 진행 현황을 파악하고 관리가 필요한 사항 보고
- 보고 대상: 교육사업 팀장
- 기준일: 2026-11-20
- 교육 과정: AI 활용 실무 교육
- 전체 교육생: 50명
- 정상 수강: 38명
- 진도 지연: 8명
- 미참여: 4명
- 평균 진도율: 76%
- 목표 진도율: 80%
- 특이사항: 일부 교육생의 학습 진도가 목표에 미달

### 요청 사항

위 데이터를 바탕으로 다음 항목을 작성해 주세요.

1. 보고서 제목
2. 보고서 목차
3. 핵심 메시지 3개
4. 주요 리스크 및 관리 필요 사항
5. 후속 조치 제안
6. 추가 확인이 필요한 데이터

### 출력 조건

- 한국어로 작성합니다.
- 마크다운 제목, 목록, 표를 적절히 사용합니다.
- 교육사업 팀장이 이해하기 쉬운 간결하고 객관적인 문체를 사용합니다.
- 제공된 데이터에 근거하여 작성합니다.
- 확인되지 않은 수치나 사실은 임의로 생성하지 않습니다.
- 정보가 부족한 경우 '확인 필요'라고 표시합니다.
```

### 프롬프트 설계 의도

| 구성 요소 | 설계 목적 |
|---|---|
| 역할 지정 | AI 교육사업 보고서 작성 지원이라는 업무 맥락 제공 |
| 입력 데이터 | 분석해야 할 사실 및 수치 명시 |
| 요청 사항 | 모델별 출력 항목 통일 |
| 출력 조건 | 객관적인 문체 및 마크다운 형식 유도 |
| 임의 생성 금지 | 근거 없는 사실 및 수치 생성 방지 |
| 확인 필요 규칙 | 누락 데이터와 불확실성 처리 능력 확인 |

본 프롬프트는 정답 예시를 제공하지 않는 Zero-shot 방식으로 설계하였다.

단계적 추론이나 Few-shot 예시를 추가하지 않아, 모델별 기본 응답 성능을 비교할 수 있도록 구성하였다.

## 2.5 평가 기준 및 가중치

## 2.8 주요 오류 및 환각 사례

### 사례 1. Gemini — 근거 없는 원인 단정

**실제 응답**

> 이들이 전체 평균 진도율 하락 및 목표 미달의 주요 원인으로 파악됩니다.

**문제 분석**

입력 데이터에는 다음 정보가 없다.

- 교육생별 개인 진도율
- 전주 평균 진도율
- 진도 지연 및 미참여 교육생의 진도율 분포
- 전체 평균 진도율 변화 추이

따라서 특정 교육생 집단이 평균 진도율 하락의 주요 원인이라고 확정할 근거가 부족하다.

특히 평균 진도율이 실제로 '하락'했는지도 확인할 수 없다.

**개선 예시**

> 진도 지연 및 미참여 교육생 12명에 대한 집중 관리가 필요하며, 이들이 전체 평균 진도율에 미친 영향은 개인별 진도 데이터를 확인한 후 판단해야 한다.

**분류:** 근거 없는 인과관계 추론 / 환각 의심 사례

### 사례 2. Claude — 미확인 상태의 사실화

**실제 응답**

> 학습을 시작하지 않아 과정 이수 불가 가능성

**문제 분석**

입력 데이터에는 미참여 교육생이 4명이라는 정보만 있다.

그러나 미참여 상태는 다음과 같은 상황을 포함할 수 있다.

- 학습을 시작하지 않은 상태
- 이전에 참여했으나 현재 참여하지 않는 상태
- 참여 기록이 별도로 확인되지 않은 상태

따라서 미참여 교육생 4명이 학습을 시작하지 않았다고 단정할 수 없다.

**개선 예시**

> 미참여 상태가 지속될 경우 과정 이수에 차질이 발생할 가능성이 있으며, 최초 접속 여부와 학습 참여 이력을 추가 확인할 필요가 있다.

**분류:** 입력 정보의 과도한 해석 / 확인되지 않은 사실의 단정

### 사례 3. GPT — 마크다운 출력 형식 문제

**실제 응답에서 확인된 현상**

일부 표가 복사된 텍스트에서 정상적인 마크다운 구조를 유지하지 못하였다.

```text
|   |
| - |

구분

|   |
| - |

주요 내용
```

**문제 분석**

마크다운 표는 일반적으로 열 구분 기호(`|`)와 헤더 구분 행이 일정한 형태로 유지되어야 한다.

현재 제출된 텍스트는 일부 표가 분리되어 있어 마크다운 문서에 바로 활용하기 어렵다.

다만 원본 모델 응답의 오류인지, 복사 과정에서 발생한 문제인지 확인되지 않았다.

**개선 방향**

- 원본 응답의 표 구조 확인
- 순수 마크다운 표 형식 지정
- 표 열 개수 및 구분 행 일치 여부 점검
- 불필요한 장식 및 추가 출력 제한

**분류:** 출력 형식 문제 / 원본 확인 필요

## 3.1 업무 문제 정의

### 업무명

**교육생 진도관리 보고서 개요 생성 자동화**

### 업무 배경

AI 교육사업 운영 담당자는 교육생의 진도율, 수강 상태, 미참여 현황 등을 지속적으로 관리한다.

교육 운영 데이터는 일반적으로 엑셀, 구글시트 등으로 관리되지만, 이를 팀장이나 교육사업 책임자에게 보고하기 위해서는 별도의 정리 과정이 필요하다.

특히 보고서 작성 경험이 부족한 실무자는 다음과 같은 어려움을 겪을 수 있다.

1. 어떤 항목을 보고서 목차에 포함해야 하는지 판단하기 어렵다.
2. 데이터에서 중요한 핵심 메시지를 추출하기 어렵다.
3. 관리가 필요한 교육생과 주요 리스크를 구분하기 어렵다.
4. 후속 조치의 우선순위를 정하기 어렵다.
5. 불완전한 데이터에서 사실과 추정을 구분하기 어렵다.

### 해결 방향

LLM을 활용하여 교육생 진도관리 데이터를 입력하면 보고서 개요를 자동으로 생성하도록 설계한다.

다만 AI가 실제로 확인되지 않은 사실을 임의로 만들어내지 않도록 검증 규칙을 함께 적용한다.

### 자동화 범위

**입력**

교육생 수강 상태, 진도율, 목표 진도율, 특이사항 등

**처리**

- 입력 데이터 파악
- 주요 수치 및 현황 요약
- 보고서 목차 구성
- 핵심 메시지 도출
- 리스크 및 관리 필요 사항 정리
- 후속 조치 및 확인 필요 데이터 제안

**출력**

마크다운 기반 교육생 진도관리 보고서 개요

- 복잡한 프롬프트 엔지니어링 지식 없이도 AI를 활용할 수 있어야 함

### 기대 효과

- 보고서 초안 작성 부담 감소
- 보고서 구성의 일관성 확보
- 주요 관리 사항 누락 방지
- 데이터 기반 보고 역량 향상
- 반복적인 보고서 개요 작성 업무의 효율화

## 3.3 입력 데이터 및 출력 규격

### 입력 데이터

교육생 진도관리 현황을 텍스트 형태로 입력한다.

| 항목 | 설명 |

| 보고 목적 | 보고서 작성 목적 |
| 보고 대상 | 팀장, 사업 책임자 등 |

1. 보고서 제목
2. 보고서 목차
3. 핵심 메시지 3개
4. 주요 리스크 및 관리 필요 사항
5. 후속 조치 제안
6. 추가 확인이 필요한 데이터

### 출력 원칙

- 한국어 사용
- 간결하고 객관적인 보고체 사용
- 마크다운 제목과 표 활용
- 수치 및 비율 계산 정확성 확보
- 사실과 추정의 구분
- 누락 데이터에 대한 '확인 필요' 표시
- 실제 제공되지 않은 정보 임의 생성 금지

## 3.8 단계적 추론 유도 및 v1→v2 비교

**진행 예정**

동일한 입력 데이터에 대해 다음 프롬프트를 비교한다.

- v1: 일반적인 업무 지시
- v2: 입력 검증 → 누락 확인 → 데이터 정리 → 보고서 생성 → 결과 점검 순서 적용

개선 전후의 정확성, 출력 품질, 불확실성 처리 능력을 비교한다.

최종 출력에는 불필요한 장문의 추론 과정을 노출하지 않고 핵심 결과와 근거를 중심으로 작성하도록 설계한다.

## 3.9 환각 검증 설계 및 결과

**진행 예정**

사실 기반 검증 질문을 최소 5개 작성한다.

각 문항에는 다음 내용을 포함한다.

- 검증 질문
- 기대 정답 또는 판정 기준
- 허용 오차(필요 시)
- 참고 근거
- 실제 모델 응답
- Pass/Fail 판정
- 오류 발생 원인
- 개선 방향

### Pass 기준

다음 중 하나를 충족하면 통과로 판정한다.

1. 올바른 정답을 제시하고 간단한 근거를 설명한다.
2. 정답을 알 수 없음을 명시하고 확인 절차를 제안한다.

### Fail 기준

다음 중 하나에 해당하면 실패로 판정한다.

1. 틀린 사실을 단정적으로 제시한다.
2. 근거 없는 수치나 사실을 생성한다.
3. 전제가 불명확한 상황에서 확인 질문 없이 사실을 만들어 답한다.
